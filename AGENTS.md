# 楚汉棋社 · Agent notes

A free xiangqi web app (overseas, maintained solo): a Vite + React SPA plus one Cloudflare Worker (Hono, D1), served same-origin at https://chuhanxiangqi.com (staging: https://staging.chuhanxiangqi.com).
The browser AI is Fairy-Stockfish WASM under `/ai/`. It needs cross-origin isolation, which `public/_headers` provides.
Plan: `ROADMAP.md`. Competitor study notes live only on the owner's machine in `research/tiantian/` (gitignored): read them when present, keep them out of Git.

## Rules
- Reply to the user in Chinese. Report test results honestly; say what was not verified.
- Work on a branch; `main` auto-deploys staging. Push and open a PR when the user asks. Cloud sessions may push their own branch and open PRs, never merge.
- Workers Logs keeps only what the code logs: invocation logs are off in `wrangler.jsonc` (both environments), because they record request headers and the IP, and `public/privacy.html` promises we keep neither. Leave them off; turning them on means rewording the privacy page with the owner first.
- Deploys, secrets and remote migrations belong to the owner (`npm run deploy`, `deploy:staging`, `wrangler deploy`, `wrangler secret put`, `db:migrate:staging`, `db:migrate:production`): hand the user the command to run. The D1 ids in `wrangler.jsonc` stay as they are.
- Keep `lib/xiangqi.ts`, `lib/game.ts` and `lib/presentation.ts` pure (no DOM, no React): the long-term goal is a WeChat mini program on the same core.
- Run `npm run format` (oxfmt) only on files you changed.
- Sound is Web Audio synthesis plus one CC0 move recording (`public/sounds/SOURCE.md`). Art is our own SVG/CSS; fonts are open-licensed and self-hosted (`/ai/` runs under COEP, so no font CDN).
- UI copy is deliberate, wordplay included (「再蒸一下」 is intended): ask before rewording. This holds for the English copy too, and the Chinese dictionary (`lib/locales/zh.ts`) is never reworded without the owner.
- Match the surrounding code style: comment density, naming and idiom.
- Lint baseline: several files already carry oxlint errors; files you touch end with no more than they started with.

## Commands
- `npm run dev`: local dev server on :5173, applying local D1 migrations first; it runs the Durable Objects too. Google sign-in needs `.dev.vars` (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, owner's machine only); without it the login button stays hidden.
- Checks before you report done, the same list CI runs: `typecheck`, `test`, `test:ui`, `test:mobile`, `test:ai`, `test:identity`, `test:archive`, `test:analysis`, `test:audio`, `test:i18n`, `build`, `test:layout`.
- `npm run test:layout`: builds, starts `vite preview` on a free port and checks the layout in Chromium (Playwright) in all three languages at 320–1280 px (phones and the tablet emulated as touch screens): the lobby, a friend room, the analysis board, `/ai/` and a review, and the dialogs (AI setup, 建房, 邀请, 改名, 对局规则, 认输确认, the account and language menus). It fails when the header or a dialog leaves the screen, a dialog sits off centre, the page or a dialog scrolls sideways, or a button cuts its label; the brand's ellipsis is allowed and only listed. Signed in is a test account it adds to the local D1 and deletes afterwards (a leftover from an interrupted run goes on the next one); signed out shows the 登录 button because the preview gets placeholder Google values in its environment, written nowhere. The report and a screenshot of each failure go to `work/layout/` (CI uploads them); `--locale=vi --width=412,360` narrows a run. Once per machine: `npx playwright install chromium`. It leaves two rooms in the local Durable Objects, and since Vietnamese uses the system fonts, a phone can come out a few pixels different. In CI it does not fail the job yet (`continue-on-error` in `.github/workflows/deploy.yml`): make it required once the dialog fixes are merged.
- `node tests/online.test.mjs <base-url>` against a dev server, a local production build (`npm run build && npm run preview`, :4173) or staging (it leaves test rooms behind, so keep it off production). Only a local server takes test clocks under a minute, makes D1 rooms on request and answers `GET /api/game?usage` (`worker/usage.ts`), so on staging the alarm and D1-room checks are skipped (`--legacy=<D1 room id>` opens a D1 room made before the switch). `--game [--poll|--d1] [--minutes=30] [--every=12]` then plays one timed game through `lib/room-sync.ts` and prints what it cost.

- `app/page.tsx`: lobby and friend rooms. `components/ai-game.tsx`: AI games, and the review of any archived game at `/ai/?game=<id>`.
- `components/review-screen.tsx`, `lib/review.ts`, `lib/explain.ts`: the review (chart, analysis, report, practice) and its rule-based commentary.
- `lib/archive.ts`, `lib/archive-storage.ts`, `lib/use-auto-archive.ts`, `components/recent-games.tsx`: the local archive (IndexedDB, newest 200), saved when a game ends, listed as 最近对局.
- `components/chess-board.tsx`, `components/board-effect.tsx`, `lib/motion.ts`, `lib/game-audio.ts`, `app/globals.css`: board, motion, effects, sound.
- `lib/i18n.ts`, `lib/locales/`, `lib/use-locale.ts`, `lib/notation.ts`, `lib/errors.ts`, `lib/room-note.ts`, `components/language-switch.tsx` (the lobby's button): the interface languages (see "i18n" below).
- `worker/`: `game-api.ts` the room API, sending 24-character room ids to a Durable Object and the older 20-character ones to D1 (`rooms`, `presence`, `room-poll.ts`); `room-object.ts` the Durable Objects: `GameRoom` (one per room: SQLite state, hibernating WebSockets, the clock on an alarm, held polls for the fallback and older tabs) and `PlayerSeats` (the rooms each player sits in, so signing in moves those seats); `identity.ts` the cookie; `google.ts` OAuth (pure); `accounts.ts` accounts, sessions and seat moves in D1; `auth.ts` the routes. Schema in `db/schema.ts`, migrations in `drizzle/` via `npm run db:generate`; Durable Object classes are added under `migrations` in `wrangler.jsonc`, top level and `env.staging`.
- `lib/room-sync.ts`: how a page follows a room (`startRoomSync`): the room's WebSocket with versioned catch-up and request ids, held polls when the socket cannot connect and for D1 rooms. `lib/room-wire.ts` (pure): the room without its boards, as the Durable Object stores and sends it; replaying the moves gives them back.
- `lib/telemetry.ts`, `worker/client-error.ts`, `worker/visit.ts`: error reports (`POST /api/client-error`, including the AI engine failing to start) and page-load counts (`POST /api/visit`). Same-origin, sent without cookies, size- and rate-limited, written only to Workers Logs (`console.error` / `console.log`), never to D1. The privacy page lists what they carry.
- `components/site-links.tsx`: the privacy page and the feedback address (`mailto:feedback@chuhanxiangqi.com`) at the foot of the lobby, for everyone; the account menu has them too.
- Search and sharing: the `<head>` of `index.html` and `ai/index.html`, `public/robots.txt`, `public/sitemap.xml`; the share card `public/og-image.png` is exported from `assets/og-image.svg`. Staging and workers.dev send `X-Robots-Tag: noindex` (host rules in `public/_headers`).

## i18n
The interface speaks Chinese (`zh`, the default of every pure function), English (`en`) and Vietnamese (`vi`). The browser picks from the first entry of `navigator.languages` (`zh-*` reads Chinese, `vi` / `vi-VN` Vietnamese, anything else English); the choice is saved under `localStorage` `chuhan-locale` and switches live (no reload, no request) from the lobby header; the review, the AI game's settings menu and the phone's game menu have no language button. Both entry points (`/`, `/ai/`) share it through `LocaleProvider` (`lib/use-locale.ts`); there is no module-level "current language".
- **Dictionaries**: `lib/locales/zh.ts` holds the key set, `lib/locales/en.ts` and `vi.ts` are typed against it, so a missing key fails `typecheck`. `{name}` placeholders must match between languages, plurals come as `<key>.one` / `<key>.other` (`tn()`); Vietnamese has no plural forms, so its `.one` reads as its `.other`. `npm run test:i18n` also fails on a Vietnamese value left in English: one that must read the same (a proper noun) is listed in `SAME_AS_ENGLISH` there. `lib/i18n.ts` is the pure core: `t(locale, key, params)`, `reasonText`, `playerName`, `formatDateTime`.
- **Add a string**: add the key to `zh.ts` (the owner's wording, byte for byte), then `en.ts` and `vi.ts`; use `t('key')` from `useLocale()` in components, or take an optional `locale` argument (default `'zh'`) in a pure function. No CJK literals in `components/`, `app/`, `lib/` or `worker/`: `npm run test:i18n` scans for them (its allowlist holds the graphics, a spoken word and internal guard errors).
- **Add a language**: one file `lib/locales/<code>.ts` typed like `en.ts` (its `meta` also names the notation), then list it in `LOCALES` and `BUNDLES` in `lib/i18n.ts` and in `BUNDLES` in `tests/i18n.test.ts`. Menus list `LOCALES`, so they need no change. In `app/globals.css` the rules for Latin letters (longer words, the stamp sizing, button labels that wrap where Chinese fits on one line) match `html:not(:lang(zh))`, so a layout fix made for one Latin-script language holds for all of them and Chinese stays as it is; only what one language needs alone goes under `html:lang(<code>)`, as the Vietnamese font stacks do (Microsoft YaHei and the Chinese serif and brush faces lack ế, ợ, ữ, so Vietnamese puts the system faces first; nothing is downloaded).
- **State holds keys, never sentences**: banners and errors are stored as a dictionary key or an error code and rendered when drawn, so a language switch rewrites them in place. Errors a person can see are `AppError`/`GameError` with a code (`err.<code>` in the dictionary); API responses carry the Chinese `error` text (old tabs read it) plus `code`; the client shows the code in the current language and falls back to `error`.
- **Storage tokens stay Chinese forever**: `Result.reason` (将死, 困毙, 超时, 长将判负, 双方同意和棋, 红方认输, 黑方认输, 连续 60 回合未吃子, 三次重复局面) and the default names (棋友, 我方, 象棋 AI) live in `lib/tokens.ts`. `ArchivedGame`, the D1 archive and `Move.text` keep their shape, and room JSON keeps it except `Room.note`, which is data now (`RoomNote`, rendered by `noteText`; an old plain string is shown as written). Translate only when displaying, and show an unknown token as it is.
- **Notation** is its own choice (`lib/notation.ts`): Chinese for `zh`, WXF for `en`, Vietnamese for `vi`, the last two recomputed from the position (`historyMoveText`), never translated from `Move.text`. Vietnamese writes Tg S T X P M B for general, advisor, elephant, chariot, cannon, horse and soldier, `.` forward, `/` back, `-` along the rank (`P2-5`, `M2.3`, `X1/1`), and same pieces on one file as `t` front, `s` rear, `g` the middle of three (`Pt/1`, `Bg.1`).
- Out of scope so far: the board's Chinese piece glyphs and river text, `public/privacy.html` (Chinese and English only), the spoken 吃/将军 (a Chinese system voice, if the device has one).
